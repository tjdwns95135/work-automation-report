기존 업무 방식

원료 하나를 발주하려면 담당자가 아래 과정을 매번 수작업으로 이어붙여야 했습니다.

  • 소요량 계산 — 제품별 배합비 × 생산수량을 엑셀에 옮겨 손으로 산출
  • 부족분 판단 — 소요량을 재고장·공장별 현황과 하나씩 대조
  • 1·2공장 합산 — 같은 원료가 공장마다 다른 코드로 흩어져 코드별로 수기 합산
  • 이관·결재 — 공장 간 옮길 원료는 단가를 찾아가며 결재 상신
근본 제약

ERP에 API가 없는 데다, 품목별 배합비조차 한 화면에서 확인할 수 없어 계산에 필요한 데이터를 모으기 어려웠습니다.

현재 상태 보류

  • 구현 — 소요량·부족분 계산, 발주·이관 로직, 웹앱까지 개발했습니다.
  • 보류 사유 — 정식 운영하려면 ERP에서 품목별 배합비·투입원료·원료 특이사항·단가를 안정적으로 연동해야 하는데, ERP측 견적이 3,700만원으로 제시됐습니다.
  • 계획 — 위 네 항목이 한 화면(탭)에서 함께 조회되는 범위로 좁혀 재견적을 요청하고, 비용을 확인한 뒤 진행 여부를 판단합니다.

왜 단일 도구로는 안 됐나

"전/후 이미지를 통째로 AI에 주면 되겠지" 했지만, 바뀐 곳을 놓치거나 없는 걸 지어냈습니다(환각). 아래 벽들 때문에 도구를 겹쳐야 했습니다.

  • 내용은 잘게 잘라 줘야 정확 — 통째로 주면 뭉개짐 → 영역 크롭
  • "무엇이 바뀌었나"와 "어디가 바뀌었나"는 다른 문제 — 위치는 AI가 특정하지 못함 → OCR로 위치 좌표(Microsoft OCR 사용)
  • 크기·비율이 다른 전/후 — 대응 영역끼리 짝지어 정렬하는 로직 별도
  • QR코드 — 눈으로도 OCR로도 못 읽음 → 디코딩으로 내용 비교
정리

크롭 + 정렬 + OCR + AI + QR 디코딩을 겹쳐야 겨우 실무 근처에 갔고, 어떤 AI가 맞는지는 돌려봐야만 알 수 있어 모델을 계속 바꿔야 했습니다.

근본 한계 — 단발형 API의 벽

이 검수는 한 세션에서 여러 번 반복해 되짚어야 겨우 잡히는 일입니다. 단발형 API 호출로는 그 반복 검토를 따라가지 못해, 문턱을 못 넘고 비용(건당 약 650원)만 쌓였습니다.

자동화 유지
약 650원 / 건
반복 검토 불가 → 정확도 부족 → 사람이 재확인 → 비용은 비용대로.
채택
Claude Pro 구독 1개
월 구독 1개
세션에서 반복 검토가 가능 → 정확도도 낫고, 팀이 공용으로 쓰니 비용도 이득.
