Part 1 · 성공 사례

1구매 발주 자동화

구매팀이 매일 하던 "오늘 무엇을, 얼마나 발주할지" 계산을 사람이 하지 않도록 만든 프로젝트입니다.

1-1기존 업무 방식 — 왜 힘들었나

원료 하나를 발주하려면 담당자가 아래를 매번 손으로 이어붙여야 했습니다.

  • 소요량 계산 — 제품별 배합비·투입원료를 일일이 엑셀로 옮겨 "이 제품 이만큼 만들려면 원료가 얼마나 드는지" 계산
  • 부족분 판단 — 그 소요량을 재고장 엑셀 + 공장별 원료현황과 손으로 대조하며 모자란 양 산출
  • 1·2공장 합산 — 같은 원료가 공장마다 다른 코드로 흩어져 있어 코드별로 일일이 합산(누락·중복 발생)
  • 이관·결재 — 공장 간 옮길 원료는 따로 모아 단가를 찾아가며 결재 상신
그 결과

⏱ 시간 소모 · ❌ 휴먼 에러 · 🔀 데이터 분산(ERP·재고·배합비·단가가 전부 따로) · 👤 담당자 한 명에게 묶이는 속인화

1-2문제의 뿌리 — "ERP에서 데이터를 못 꺼낸다"

모든 수작업의 원인은 하나였습니다. ERP에 API가 없어, 품목코드·품목명으로 배합비·투입원료를 자동으로 끌어올 수 없다는 것. 그래서 계산의 재료가 되는 데이터부터 사람이 옮겨야 했습니다. 문제를 "데이터 확보"와 "자동 파이프라인" 두 갈래로 나눠 정면 돌파했습니다.

1-3어떻게 접근했나 — 프로세스 정의

① 데이터 확보 ERP사에 공문 발송
품목코드·품목명별 배합비·투입원료를 엑셀로 정식 수령. (동시에 API 지원을 별도 요청해 2차 고도화의 발판 마련)
▼
② 자동 수집 남는 노트북 1대 + 화면 자동화
API가 없으니 ERP 화면을 자동으로 조작(pywinauto)해 필요한 정보를 엑셀로 내보내고, 그걸 DB에 자동 적재·주기 갱신. 사람 개입 없이 최신 상태 유지.
▼
③ 웹앱 한곳에서 계산 자동화
담당자는 제품만 등록. 나머지(소요량·부족분·발주·이관)는 웹앱이 모아둔 데이터로 자동 계산.
핵심 아이디어

"ERP에 API가 없다"는 제약을 공문(데이터 확보) + 화면 자동화(파이프라인)로 우회했습니다. 기술이 안 되면 프로세스로 푼 것입니다.

1-6왜 이렇게 만들었나 & 기대효과

  • 왜 웹앱인가 — 구매팀 전원이 URL·로그인만으로 접속. 개인 PC 설치·엑셀 버전 관리가 필요 없음
  • 왜 관리형 DB인가 — 서버를 직접 운영하지 않아도 됨. 흩어진 규격·배합비·단가·재고·소비기한을 한곳에서 유기적으로 연결
  • 사람의 시간을 어디로 — 반복 계산에서 풀려난 시간을 거래처 관리·단가 협상·안전재고 정책 같은 판단 업무로 전환
  • 속인화 해소 — 계산 로직이 시스템에 있으니 담당자 부재·이직에도 업무가 멈추지 않고 인수인계가 쉬움
  • 확장성 — 같은 구조로 타 공장·품목군에 확대 적용 가능

현재 상태 — 웹앱으로 배포 완료되어 실사용 가능한 상태입니다. (다음 단계: ERP사의 API 지원이 확정되면 엑셀 수령을 API 직접 연동으로 대체하는 2차 고도화)

Part 2 · 중단 사례

2영업지원 표시사항 비교

영업지원팀의 라벨 검수를 자동화하려던 시도입니다. 기술적으로는 상당히 끌어올렸지만, 비용 대비 효과가 안 나와 스스로 중단했습니다. 실패한 이유를 정직하게 정리합니다.

2-1어떤 업무였나

건강기능식품 케이스(단상자·설명서·라벨)의 표시사항(라벨 문구)이 개정될 때, 영업지원팀은 변경 전 도안과 변경 후 도안을 나란히 놓고 한 글자씩 눈으로 대조하며 바뀐 곳을 찾아야 했습니다.

  • 조밀한 한글 문단에 낀 한두 문장·한 글자 변경도 놓치면 안 됨 — 규제 검수라 누락 = 리스크
  • 파일 크기·비율이 다른 전/후(전개도·재촬영본)를 눈으로 맞춰보는 것 자체가 피로하고 오래 걸림
  • QR코드처럼 눈으로는 같아 보여도 내용이 바뀐 경우는 사실상 확인 불가

2-2어떤 방식으로 접근했나

"업로드하면 자동으로 바뀐 곳을 찾아 하이라이트하고, 검수용 PDF까지 뽑아준다"를 목표로 파이프라인을 만들었습니다.

2-3정확도를 올리기 위한 기술 여정

"어떤 AI를 쓰느냐"를 계속 바꿔가며 정확도와 비용·속도의 균형을 찾으려 했습니다. 그 과정이 곧 이 프로젝트의 한계를 보여줍니다.

1
GPT-4o API로 시작
가장 먼저 시도한 방식.
조밀한 문단의 변경을 요약해 놓치거나, 없는 성분을 지어내는(환각) 문제
2
Gemini API로 전환
모델을 바꿔 정확도·비용을 개선해보려 시도.
3
Claude(구독형 CLI)로 전환
정확도가 좋아 검토했으나 —
세션 사용이 몰릴 때 한 건 처리에 15분 이상 소요. 계정 공유는 약관 위반이라 팀 도구로 부적합
4
Gemini API + Microsoft OCR 연동
두 엔진을 함께 써 정확도를 실제로 끌어올린 최종 구성.
그럼에도 한 건당 약 650원을 지불하며 돌릴 만한 정확도에는 도달하지 못함
⛔
중단(드롭) 결정
기술을 더 붙일수록 비용은 오르는데, 규제 검수가 요구하는 "거의 놓치지 않는" 신뢰 수준에는 계속 못 미쳤습니다.

2-4왜 드롭했나 — 비용 대비 효과

판단의 핵심

이 업무는 규제 라벨 검수입니다. 놓친 변경 하나가 곧 규제 리스크이므로 "거의 100% 잡아내는" 신뢰도가 전제입니다. 한 건당 650원을 내면서도 그 신뢰도에 못 미치면, 결국 사람이 다시 전수 확인해야 합니다. 그러면 자동화 비용은 순수 추가 비용이 됩니다.

같은 650원을 어디에 쓰는 게 이득인지 비교해봤습니다.

2-5영업지원팀 의견

영업지원팀도 "이 돈이면 Claude Pro 계정 하나 구독해서 팀이 돌려 쓰는 게 낫다"는 결론에 동의했습니다. 실제 사용자인 팀의 판단과 개발자의 판단이 일치한 만큼, 자동화를 무리하게 끌고 가지 않고 합리적으로 중단하는 것이 맞다고 보았습니다.

맺음말 — 자동화의 기준

  • 구매 발주는 계산이 규칙으로 딱 떨어지고 반복량이 커서, 자동화가 시간·정확도·속인화 해소로 확실히 남는 장사였습니다 → 유지·고도화.
  • 표시사항 비교는 "거의 완벽"이 전제인 규제 검수인데 AI 정확도가 그 문턱을 못 넘어, 건당 비용이 순손실이 되었습니다 → 더 싼 대안(Claude Pro 수동)으로 대체하며 중단.

두 건 모두 "만들 수 있느냐"가 아니라 "비용 대비 이득이냐(ROI)"로 판단했습니다. 될 것은 끝까지 밀어붙여 배포했고, 안 될 것은 감정 없이 접었습니다.

본 보고서는 사내 보고용으로 작성되었으며, 배합비·단가·거래처·접속정보 등 영업비밀 및 민감정보는 일절 포함하지 않았습니다.
